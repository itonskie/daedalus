# ADR 5: Cached demos are the default first-run state

**Status:** Accepted
**Date:** 2026-07-08

## Context

The demo's opening moment sets the portfolio story. Options:

- **Blank viewport, "type a prompt to begin."** Traditional. Puts effort on the visitor.
- **Loading spinner while we call an LLM.** Broken from the start if the visitor hasn't configured a provider.
- **Pre-rendered cached scene.** Zero-config, works immediately.

The PRD is explicit that user story #1 ("as a portfolio visitor with no setup, I want the page to load into a working voxel scene") is a hard requirement — the demo cannot ever look broken on first load.

The upstream provider surface (Anthropic BYOK key, Ollama URL) requires configuration a fresh visitor does not have. A cold visit with no provider must still show *something worth looking at*.

## Decision

**Ship the six canonical prompts × two models as 12 checked-in `.js` files under `demos/`. Zustand initializes with one cached demo already loaded into `lastGoodGrid`.**

- Default demo: `castle-with-four-towers/claude-sonnet-4-6.js` — most visually striking of the six.
- The chat panel shows six prompt chips; clicking any chip loads its cached demo (until the visitor configures a live provider).
- Cached demos are not a `LLMProvider` — they're a store-level shortcut that bypasses the LLM call entirely. Provider selection is a UI concern; cached is the *default state*, not a fake provider.
- The Compare Models view is cached-only — see [PRD user story #21](../specs/prds/2-daedalus-mvp-llm-generated-voxels.md).

## Alternatives Considered

**Blank viewport with a "click to generate" prompt.** Rejected: forces the visitor to configure a provider before seeing anything. Kills the zero-friction portfolio story.

**Auto-generate on load using a hard-coded Anthropic key.** Rejected: cost, security, and it makes the demo dependent on the maintainer's API key not being revoked.

**Fetch cached demos from a CDN at runtime.** Rejected: adds a runtime network dependency for a demo whose selling point is `git clone && pnpm dev`. Vite's `?raw` glob bundles the files into the app at build time — no runtime fetch.

**Only cache one prompt (the default).** Rejected: the Compare view and the "browse the range" story (user story #2) need all six.

## Consequences

**Positive:**
- First-load experience is a rendered scene, not a form.
- Compare view works offline — no keys, no Ollama required.
- Cached demos exercise the same sandbox path as live generation — a broken cached demo signals a broken sandbox contract (regression guard).
- `.js` files diff cleanly in PRs — a reviewer can read what the models produced without running anything.
- `pnpm bench` can regenerate them on demand from a maintainer laptop with both providers configured.

**Negative:**
- **Cached demos age.** If the system prompt changes or the palette expands (see [ADR 4](4-named-palette-enum.md)), cached demos may fail to execute. Mitigation: CI smoke test loads every cached demo through the sandbox and asserts `ok: true`.
- **Twelve files checked in.** ~50 lines each. Fine — they're the artifact.
- **Model-slug drift.** If Anthropic renames a model, the cached filename becomes historical. Acceptable — cached demos are a snapshot; refreshing them with a new model slug is a normal `pnpm bench` run.
- The default state is aesthetically load-bearing — picking a weak default demo makes the whole demo feel weak. Chose `castle-with-four-towers` for structural drama.
